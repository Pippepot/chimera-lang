# Language syntax and semantics
# Source of truth for the language, but incomplete. ROADMAP.md tracks planned work.
# Unspecified behavior remains open; parser or legacy behavior does not define it.
# Examples are independent; undeclared names stand for surrounding context.
# Everything after '#' to the end of a line is a comment.
# Delimited argument, parameter, element, and initializer lists may span lines.
# Indentation at list boundaries is continuation whitespace; commas separate
# entries, and a final comma is allowed. Grouping and index expressions may also
# span lines. Indented bodies introduced by if, loop, struct, or a function
# retain their block meaning inside delimiters. A comma or closing delimiter
# may end such an expression body before its physical dedent.


# Types and evaluation
# int: signed 32-bit integer; +, -, *, /, and negation wrap modulo 2^32.
# Signed division truncates toward zero, so min-int / -1 wraps to min-int.
# Division by zero is an execution error; at compile time it is a source error
# at the executed division.
# Remainder (%) satisfies left == (left / right) * right + left % right under
# wrapping: a nonzero remainder has the sign of its left operand, and
# min-int % -1 is zero. Remainder by zero is an execution error, reported at
# the executed operation at compile time.
# byte: distinct unsigned 8-bit integer, values 0 through 255, size and
# alignment 1. It has trivial move, copy, and drop, but no arithmetic or
# comparison operations yet.
# int_literal: compile-time-only type of decimal integer literals. A unary
# minus applied directly to an integer literal belongs to the literal. Without
# an expected type, an int_literal value defaults to int; values outside int's
# range are source errors. std converts int_literal to byte for values 0
# through 255; other values are source errors. No converter relates int and
# byte values in either direction.
# float: floating-point number.
# bool: true or false.
# type: the type of compile-time type values.
# unit: single-valued type; its value is unit, also written ().
# none: distinct single-valued type; its value is none.
# In ordinary expression contexts, unit and none denote their values. A `type`
# annotation or the result expression of a function returning `type` interprets
# them as type values; the enclosing function's return type does not change
# their meaning in arguments, local initializers, or other nested expressions.
# never: bottom type for expressions that never return.
# Evaluated subexpressions execute once, left to right in source order.
# An init argument defers its entire expression until destination construction;
# forwarding does not evaluate it, and an ordinary return may skip it.
# Struct initializers evaluate in initializer order, not field declaration order.
# Reordering is allowed only when unobservable.


# Operation functions
# An operation function is a type-namespace member with a compiler-specified
# signature. Namespace visibility and ordinary call/specialization rules apply;
# arithmetic, comparison, and indexing lookup uses the left operand's defining
# namespace, independently of imports. Membership uses the collection on the right.
# No fallback to the right operand or implicit merging of same-named declarations
# participates in selection. Explicit overload sets use the rules below.
# Operands evaluate once, left to right.
# Primitive type namespaces belong to the registered standard prelude. Their
# operations are qualified extern declarations, with compiler-provided bodies;
# operator syntax, explicit calls, and callable values use the same declarations.
pub extern func int.+(imm left: int, imm right: int) int
# Only the registered prelude may extend primitive namespaces. Other modules
# cannot extend them, just as they cannot extend an imported struct namespace.
# Comparisons and logical operators return bool in every expression position.
# and/or skip the right operand when the left bool determines their result.
# The operation-function inventory is +, -, *, /, %, ==, <>, <, >, <=, >=, unary
# negation and read/write indexing. Logical not is dedicated control flow.
# Unary and binary arithmetic minus
# share the spelling -, distinguished only by runtime operand count. neg is an
# ordinary identifier, with no compiler-defined meaning. Parentheses do not
# change operator precedence.
# For receiver type Self, the exact signatures are:
# +, -, *, /, %: func (imm Self, imm Self) Self
# ==, <>, <, >, <=, >=: func (imm Self, imm Right) bool
# unary -: func (imm Self) Self
# []: func (imm Self, index: Index) Result; ref Self is also allowed
# []=: func (mut Self, index: Index, var value: Element) unit
# Inherited namespace static arguments and inferable static parameters use
# ordinary specialization; they do not count as runtime operands or permit
# extra runtime operands. Signature validation rejects mismatches even for
# explicit calls and callable values: addition with three operands is invalid.
# Operators have fixed identities by spelling and operand count, not argument
# types. Both forms of - may be declared in the same namespace; duplicate forms
# remain invalid. Ordinary named functions do not acquire implicit overloads.
# An explicit operator overload set owns its complete spelling and cannot coexist
# with another declaration of that spelling, including another form of minus.
# Comparison declarations choose their right operand type; ordinary argument
# conversion applies to that operand. Dispatch still uses the left operand's
# namespace and never reverses a user operation. Arithmetic operands retain
# their matching-Self signatures.
# Explicit calls select by runtime operand count or total count with explicit static
# arguments; a call matching both forms is ambiguous. A callable reference to
# both forms requires a function-type context; its parameter count selects the
# form, then ordinary signature and type checks apply. A sole form needs no
# annotation.
pub extern func int.-(imm value: int) int
pub extern func int.-(imm left: int, imm right: int) int
const negate: func(imm int) int = int.-
const subtract: func(imm int, imm int) int = int.-
# Explicitly declared sets instead select by argument types as specified below.
# Arithmetic and indexing are ordinary operations. Comparisons return bool.
# Writable indexing calls []=; compound indexing reads before preparing its RHS.
# Receivers, indices, and eager replacements evaluate once in source order.
# Standard [] bounds checks and panics on invalid access. get returns an explicit
# optional reference instead; slice returns an optional view. To handle absence,
# bind the optional result with a typed pattern before reading or replacing it.
# Standard checked reference replacement requires directly movable elements,
# automatic drop, and no contained borrowed references. Immovable elements may
# still construct in containers and be accessed through get. Readonly Span
# provides no writable element access. User indexers choose their own bounds policy.
# Assignment remains ownership-aware replacement; compound assignments combine
# the corresponding binary operation and assignment. and/or remain short-
# circuit control flow; is tests type membership. Transfer ^, field access,
# typed binding patterns, and initialization retain their dedicated
# semantics and are not eager operation functions. Predicates over explicitly
# typed compile-time-only int_literal values remain intrinsic and preserve their
# wide literal range. Equality of compile-time type metadata remains compiler
# identity comparison. Tokens with no language semantics yet (such as
# bitwise operators and shifts) are not added
# by this contract. Later numeric types use the same operation signatures.


# Collection membership
# value in collection returns bool through the visible contains member, using
# ordinary lookup, specialization, overloads, and argument conversion. Its
# signature is func(imm Collection, imm Element) bool. Both operands are borrowed.
# The value evaluates before the collection; the callee receives collection
# first. There is no iteration fallback. Logical operators compose the bool
# result normally; completed effects persist and temporary owners clean normally.
# in has comparison precedence; ranges bind more tightly. for item in collection
# has its own binding/header grammar and continues to use the iteration protocol.
# Membership in a match guard uses the same dispatch protections as other calls
# and contributes no exhaustive coverage.
if value in collection -> found()
if not (value in collection) -> missing()


# Numeric conversions (open)
# Ordinary value converters are infallible. Conversions between numeric runtime
# types that wrap, truncate, round, saturate, or widen are named functions instead.
# Their names, overflow and failure behavior, other numeric widths, and float
# literal typing remain open. Existing variant widening and typed patterns do
# not define numeric conversion behavior.


# Text and basic I/O
# A double-quoted literal has the compile-time-only type string_literal. Its
# value is the decoded UTF-8 bytes, independent of source spelling. Supported
# escapes are \", \\, \n, \r, \t, \0, \xHH (one byte), and \u{H...} (one
# Unicode scalar, one through six hexadecimal digits). The complete decoded
# literal must be valid UTF-8. Invalid escapes, malformed UTF-8, surrogates, and
# scalars above U+10FFFF are source errors. Embedded NUL is valid text. Literal
# decoding belongs to semantic analysis of demanded expressions.
# Ordinary inferred bindings default a literal to std.text.String. Under another
# expected type, a static-source converter from string_literal applies first when
# one is declared for that target. Otherwise the literal materializes at its use
# as std.text.StaticString, a copyable view of its permanent decoded bytes, and
# an ordinary converter from StaticString applies. Materialization is not a
# converter and creates no per-literal function or specialization. Literals remain
# string_literal when that type is explicitly expected, including static
# parameters. The default String uses registered standard-library identity,
# independently of prelude imports or a locally shadowing name.
# String owns either immutable literal storage or a unique growable allocation.
# Literal conversion allocates nothing. const controls mutation of the binding;
# it does not select storage. var permits mutation; reserve/append obtain owned
# storage before changing literal-backed data. static evaluates at compile time;
# literal-backed String results refer to symbolic immutable storage, never host
# addresses. Runtime descriptors and the referenced bytes have independent
# storage. String has move and automatic drop, but no implicit copy; clone is
# explicit and returns an optional variant. Allocation-backed text also executes at compile time,
# subject to the evaluation-local storage publication boundary.
# BytesView is a copyable wrapper of Span(byte) with readonly backing access.
# get returns readonly ref byte | none; [] returns readonly ref byte and panics
# on invalid access. ref bindings alias the byte, while owned
# bindings copy it. A borrowed byte can outlive a temporary view descriptor but
# not its backing owner. Views of arrays,
# allocations, Lists, and Strings retain their backing owners and storage
# invalidation dependencies. Views of literal storage have permanent origins.
# Empty views are valid and never dereference their base. View construction and
# slicing use nonnegative, overflow-safe bounds checks. No raw address escapes.
# StringView wraps a BytesView whose complete range is valid UTF-8. Construction
# from arbitrary bytes validates once and fails for malformed input; slicing
# checks both bounds and codepoint boundaries. byte_length reports bytes, not
# Unicode scalars or graphemes. Text mutation accepts only validated text and
# exposes only immutable byte views. No Unicode normalization is implicit.
# String and StringView define == and <> as infallible exact byte comparison,
# including embedded NUL bytes. Different byte lengths imply inequality.
# Both receiver types accept StringView on the right. String operands convert
# to views by borrowing, and literal operands can construct permanent views.
# String/StringView/literal comparisons therefore work in either order without
# copying or allocating text. Each implementation compares borrowed bytes.
# The named byte_int function widens a byte to int without failure. Numeric
# runtime types are still not related by converters.
# Standard String converters format int and byte in decimal, bool as true/false,
# unit as (), and none as none. StringView converts to an owned copy. Array,
# List, and Span format their elements recursively as [a, b], without quoting
# text elements; empty collections produce []. BytesView formats its arbitrary
# bytes as a decimal collection rather than assuming UTF-8. Box and Ref format
# their contents as Box(value) and Ref(value). These generic converters require
# String conversion of an element expression. Range formats omitted bounds with
# .. or ..=, matching source syntax. Converters borrow their inputs, never copy
# or consume elements, and panic on allocation failure. They also execute at
# compile time within the ordinary storage-publication boundary.
# A collection literal can initialize String directly, as in String([1, 2]);
# its consuming converter constructs an Array before formatting it. Element
# expressions use ordinary values and lifetime cleanup, not a failure channel.
# std.io supplies stdin/stdout/stderr handles, optional read_bytes, write_once,
# write_all, and write_text. Ordinary print accepts an immutable value of T
# that converts to String, converts it once, and writes
# the text followed by a newline. Existing String inputs are borrowed without copying.
# print is a generic overload export; callable references require a function-type
# context, which specializes its value type. It terminates with panic status
# 134 on allocation or output failure. Handles borrow
# the process's standard descriptors; they do not close or own them. read_bytes
# appends at most the requested bytes to a List(byte), publishing only the
# initialized prefix. Positive progress and short reads/writes are success;
# zero read indicates EOF for a nonempty request. A zero-size read returns zero
# without reading. Interrupted syscalls retry. write_all advances by completed
# counts and fails on zero progress. Output programs ignore SIGPIPE so closed
# pipes report ordinary write failure; print handles that failure by panicking.
# Other OS failures return none; earlier external effects are
# not rolled back. Reading or allocating
# failure preserves initialized List contents; reservation may change capacity.
# Writes borrow initialized readonly byte spans. Reads initialize spare allocation
# slots, not elements of a writable initialized span.
# Failure cleanup releases owned storage through ordinary lifetime rules.
# Byte I/O preserves arbitrary bytes. UTF-8 validation occurs when those bytes
# become text, so partial UTF-8 sequences can be accumulated before conversion.
# print is an ordinary declaration and may be shadowed or used as a callable.
# Reached compile-time I/O is an unavailable execution operation, even inside a
# optional result handler; an unexecuted branch performs no I/O and causes no error.
# StaticString represents immutable literal storage. Only literal
# materialization creates one; its bytes are permanent and readonly, so views of
# them may outlive every binding. Ref and Span use one private StorageCursor(T)
# substrate for typed storage access.
# Only registered storage primitives create/access cursors; cursor and handle
# permissions cannot be escalated. Neither exposes numeric addresses.


# Structural tuples
# A tuple is an ordered collection of unnamed elements, written (foo, bar).
# Its structural identity includes each element's logical type and owned/reference
# storage kind in order. Types use (A, B), with ref selecting a reference member;
# positions use .0, .1, and so on. Reference members capture existing places and
# retain independent authority and origins through copies and const carriers.
# Owned members retain their ordinary copy, move, and drop obligations.
# Parentheses without a comma group an expression or type: (x) is x.
# A trailing comma selects a singleton: (x,) has type (T,). () denotes unit,
# including in type positions; unit is not an empty tuple. Named fields belong
# to structs. An expected tuple type supplies member types and storage kinds;
# otherwise each element infers its ordinary value type and owned storage.
# This applies recursively, including tuple types returned by type factories.
const pair = (1, true)
const singleton: (int,) = (42,)

# Binding patterns use (x, y) for tuples and [x, y] for Array, List, and Span.
# Patterns nest, accept trailing commas and type annotations, and use _ to
# ignore an element without copying it. Empty () and [] patterns require unit
# and an empty sequence respectively. A sequence pattern requires exactly its
# number of elements; there is no implicit prefix or rest match. Tuple and Array
# length mismatches are source errors. List and Span check their lengths at
# runtime before extracting elements; mismatch follows the explicit handler.
# A conditional binding tests length and type patterns and exposes
# names only to its successful branch. Conditional patterns permit const/ref
# bindings; mutable conditional bindings remain unsupported.
#
# The source evaluates once. const and var copy elements of an existing source;
# ref aliases their places. Fresh results and explicitly transferred sources
# hand owned elements to owning bindings. Reference members retain their own
# authority and origins, and owning bindings copy their referents. Each leaf
# inherits the outer const/var/ref mode unless it specifies its own mode.
# Decomposing an owned tuple or Array partitions its ownership in place, so
# fresh immovable members can bind without relocation. Taking owned List
# elements requires direct movement; reference-only patterns keep its backing
# storage and can borrow immovable elements. Ignored owners and partially bound
# values retain ordinary cleanup and explicit-drop obligations on every exit.
var coordinates = (19, 23)
const (ref x, var y) = coordinates
x += 1
y -= 1
const [first, second] = [x, y]

# The same patterns bind for-loop and comprehension items. Bare leaves own
# owned items and alias borrowed items readonly; explicit const/var/ref modes
# select copying/ownership or aliasing independently per element. A pattern
# consumes neither an existing tuple nor its sequence merely by naming it;
# use ^ to transfer an existing owner. Static comprehensions accept nested
# patterns with immutable owning leaves, following ordinary static expansion.


# Standard library
# The compiler embeds the standard library. Each top-level `.chi` file in its
# `std` directory defines the reserved module `std.<filename>`; unlike ordinary
# user modules, this reserved mapping includes the filename without `.chi`.
# Every user file implicitly imports every public export of `std.prelude` into
# its unqualified scope. Compiler-owned standard-library files do not receive
# this implicit import. Current-module declarations take precedence over the
# defaults. Any explicit import whose path is exactly `std.prelude` replaces
# the implicit import for a user file, so this opts out of every prelude name:
import std.prelude.{}
# A non-empty selective import opts into only its listed names. Other standard
# library modules remain qualified or require explicit imports.
# std.math exports infallible min(int, int) int and max(int, int) int.
# They return the smaller or larger integer value, respectively, and use
# ordinary left-to-right argument evaluation at runtime and compile time.
# Its infallible clamp(value: int, lower: int, upper: int) int returns value
# restricted to the inclusive interval [lower, upper], defined as
# max(min(value, upper), lower). Reversed bounds return lower; equal bounds
# return that bound. It uses the same ordinary call semantics.


# Modules
# A folder is a module: every `.chi` file directly inside it contributes
# declarations to that module. Files create no namespace; subfolders create
# child modules. Filenames and the extension never participate in module or
# declaration identity. Module paths derive from the entry file's directory,
# which is `$entry`; subfolders append dotted segments. Parent and sibling
# folders are invisible. Directory segments must be spellable identifiers;
# other directories and their subtrees are invisible to module discovery.
# Static, function, and struct declarations are shared across every file of
# one module with no import between them. Top-level const and var bindings
# are entry-body locals, not shared declarations. File, declaration, and
# import order have no meaning.
# Imports are file-scoped and top level only: each file states its own external
# dependencies, and sharing a module does not share imports.
import physics
import physics.collision
import physics.{Body, World}
import physics as phys
import physics.{Body as PhysicsBody}
# A whole-module import exposes its full path without implicitly importing
# children. Shared leading segments navigate parent namespaces without
# importing them, so combining imports that share a prefix is harmless.
# An alias replaces the qualification. A selective import introduces the
# named declarations directly into file scope; an empty selective list is the
# empty import. A file may import its own module; the same visibility rules
# apply. A selective item that resolves to a module binds its namespace for
# qualification; namespaces never become values.
# Module-qualified lookup is valid wherever the target is valid (type, value,
# call, initializer head) and shares `.` syntax with struct namespaces. The
# first identifier resolves normally, so a local shadows a module name with no
# fallback to module lookup.
var body: physics.Body
# Unqualified lookup considers locals, then parameters, then current-module
# declarations, then the file's selective imports and aliases. A selective
# import or alias must not collide with another visible non-import declaration
# at the same file scope; locals inside functions may shadow imports. An exact
# duplicate import is harmless; one name bound to different declarations is an
# error. A repeated binding to the same target merges, preserving an export.
# Declarations are module-private by default: visible from every file of the
# same module, inaccessible elsewhere. `pub` opens a top-level static,
# function, struct, or import to importing modules; it is rejected on
# runtime const/var bindings and anywhere inside a body. Struct fields and
# namespace members take their own `pub`; see Structs.
pub struct Body
    a: int
# Imports are private by default and never create declarations. `pub import`
# re-exports under the importing module's namespace; chains share one identity,
# including nominal type identity. A re-export never enters the unqualified
# scope of sibling files: each file sees its module's declarations plus its
# own imports only.
pub import math.{Vec3}
# Module import cycles are allowed. Only a real semantic dependency cycle is an
# error, via the declaration-cycle rule.
# Any file may contain executable top-level statements, but only the file
# passed to the compiler executes them. Imported files never run on import;
# imports have no runtime side effects.
# The designated file's top-level body is an ordinary unit entry. Reaching its
# end cleans live owners and exits with status 0. A discarded false or none is
# data and does not exit the program. Explicit exit and panic retain their own
# semantics. Compile-time required evaluation can return none as an ordinary value.



# Bindings and compile-time execution
static a: int = 10 # compile-time-known, immutable
const b: int = 20  # immutable
var c: int = 30    # mutable
const d = 30      # inferred annotation

# Top-level static declarations share one namespace within their module and are
# evaluated when a consumer demands them. A declaration cycle is an error. A static type value
# introduces an alias, not a distinct nominal type; aliases preserve canonical
# structural identity when used within variants.
static Result = int | none
# Type-valued arguments accept the same complete type expressions as annotations,
# including unions, grouping, nested applications, and callable types.
static OptionalNumbers = Array(int | none, 2)
static Callbacks = Array(func(int | none) int, 2)
static Empty: type = none # annotation disambiguates a type from the value none
static Default = 40

# Static bindings are also allowed in function and block scope. Their
# initializers are evaluated at compile time, may use enclosing static
# parameters and lexically visible local static bindings, and cannot capture
# runtime parameters or locals. They are immutable and lexically scoped;
# they do not declare persistent mutable runtime storage.
func answer(static base: int) int
    static computed = base + 2
    return computed

# A variable keeps its declared or inferred type. Assignment evaluates its
# right-hand side once, widens it to that type when permitted, updates the
# variable, and evaluates to the updated value. Compound assignment uses the
# current value as the left operand of the corresponding operation.
# A field target denotes a path into its mutable root. Compound assignment reads
# the old leaf before evaluating the right-hand side. The final update writes
# the leaf into the root after right-hand-side evaluation, so changes to sibling
# fields made by that evaluation are preserved.
c = 40
c += 2

# A static initializer may call an ordinary function. Multi-statement
# computations belong in the function body.
func compute() int
    const value = 40
    return value + 2
static result = compute()

# 'comptime' currently evaluates its body at compile time. Once local static
# bindings and ordinary function-call initializers cover every comptime use
# case with the same semantics, remove the comptime keyword from the language.
# Until that coverage is verified, retain it; local static bindings above are
# required language behavior, not a claim of current compiler support.
const computed = comptime -> 40 + 2
const computed_block = comptime
    const value = 40
    value + 2

# Compile-time execution is demand-driven. Static initializers, static call
# arguments, direct calls used in type positions, and explicit comptime
# expressions are evaluated only when a consumer needs their result. They use
# the same typed operations, control flow, calls, evaluation order, coercions,
# and ownership behavior as runtime code.
#
# A compile-time function call may supply ordinary parameters with interpreted
# values. These interpreted arguments are distinct from static parameters:
# static parameters form the specialized function identity and do not occupy
# parameter slots, while interpreted arguments are passed through the function's
# ordinary typed parameter slots for that evaluation.
#
# A static initializer or comptime expression may reference module statics and
# functions, enclosing static parameters, lexically visible local static
# bindings, and bindings declared inside its own body. It cannot capture an
# enclosing runtime parameter or local, including an immutable local whose
# current value happens to be known by the compiler. Its result must be
# representable as a compile-time value.
#
# Compile-time execution is deterministic and has no ambient foreign calls,
# filesystem or console I/O, clocks, randomness, environment access, or target
# machine addresses. A future compiler service must be introduced explicitly;
# host functions are never implicitly callable. An unavailable operation is an
# error only when execution reaches it.
#
# A compile-time value consumer evaluates an ordinary typed result. none and
# error variants publish like other values when their payloads are publishable.
# Reached panic, unsupported execution capabilities, and invalid operations are
# source diagnostics; ordinary control exit retains its structured compiler result.



# Compile-time storage
# One evaluation comprises a demanded compile-time computation and its nested
# ordinary calls and deferred initializer regions. They share evaluation-local
# storage. Allocation, indexed construction and access, borrowing, mutation,
# transfer, and deallocation obey the ordinary ownership and init contracts.
# Box, List, Ref, Span, and text views use their library declarations and the same
# element capability restrictions as runtime execution.
#
# Every successful allocation creates a fresh logical identity, including
# repeated calls with equal arguments and calls with no arguments. Moving an
# owner preserves its allocation identity; copying a Ref preserves its referent
# rather than copying or acquiring the allocation. Deallocation ends that
# allocation's lifetime. Reusing backing memory cannot revive its identity.
# Successful zero-count and zero-sized-element allocations also have distinct
# identities. Logical capacity is the requested count, independent of byte size;
# zero-sized initialized elements retain their element identities and hooks.
# No compile-time operation exposes a compiler or target machine address.
#
# Allocation uses the selected host target's request rules for element
# eligibility, layout, size, and alignment. A negative count, checked layout
# overflow, unsupported resolved request, or provider refusal produces ordinary
# allocation refusal as none through the declared optional API. Compiler memory used
# to interpret values is an implementation resource: exhausting it is the
# infrastructure failure described above, not an allocation-provider refusal.
# Optimization may remove an allocation and its matching deallocation when the
# storage is otherwise unobserved; the removed request cannot then be refused.
# Allocation refusal skips deferred initialization and returns none. Ordinary
# returns clean completed subobjects and release storage as required by the owning
# library declaration; captured writes and completed transfers are not rolled back.
# Deallocation itself never destroys elements. Ordinary scope cleanup and hooks
# retain their runtime ordering and effects.
#
# Allocation-backed owners, references, and views may be passed, returned,
# stored in aggregates or variants, and copied back through mut parameters
# between calls within one evaluation, subject to their ordinary lifetime and
# capability rules. A static binding, static parameter, or other consumer of a
# canonical compile-time value instead requires publication. Publication cannot
# retain any identity of evaluation-local storage, including local or inline
# storage reached through a reference. This restriction applies recursively to
# the actual stored fields, array elements, active variant payloads, and backing
# owners of views. An inactive variant member and the element type of an empty
# array do not themselves retain storage.
#
# Ordinary data copied or validly extracted from that storage may be published
# once it retains no evaluation-local identity. Type values, callable references,
# and symbolic immutable literal storage remain publishable under their existing
# contracts. Returning an allocation-backed identity as a static initializer or
# comptime result, retaining it in specialization arguments, or materializing it
# in runtime storage is a source error. Serializing or relocating compile-time
# allocations into persistent storage remains unspecified. Cached execution
# must preserve these rules: a cached result cannot share a fresh allocation
# between calls or extend storage beyond its evaluation.
func make_twenty() Box(int) | none -> Box.new(20)
func inspect_allocations() int | none
    var first = make_twenty()
    if not (first is Box(int)) -> return none
    const second = make_twenty()
    if not (second is Box(int)) -> return none
    ref borrowed = first.borrow()
    borrowed = 22
    return first.borrow() + second.borrow()
static allocated_answer = match inspect_allocations()
    value and value is int -> value
    _ -> 0
# allocated_answer is ordinary data: 42. Both Boxes are destroyed normally.
# static escaped = make_twenty() # source error: retains evaluation-local storage


# Functions
static identity = func(a: int) int
    return a

static noop = func()
    return

static double = func(a: int) int -> a * 2

func double(a: int) int -> a * 2

func choose() func(int) int -> double

# Closures (planned)
# A capturing closure has a concrete environment containing its captures and
# code operating on that environment. Capture ownership, permission, lifetime,
# and invalidation follow ordinary value and reference rules. Borrowing a value
# does not extend its lifetime, even when the closure itself is heap allocated.
# Captures determine the environment's ownership capabilities; closures do not
# inherit the trivial move/copy/drop guarantees of plain function references.
# A concrete closure can live inline and pass through generic APIs without heap

# Parameters and transfer
# imm: read-only access (default).
# static: value supplied at compile time.
# mut: mutable access to a caller-owned variable.
# var: function-owned variable, which may be stored or returned.
# deinit: consuming ownership, preserving storage when direct movement is unavailable.
# init: pending construction into a destination supplied by the callee.
# A runtime parameter's access mode is part of callable type identity. An
# omitted mode is imm. Function declarations support static, imm, mut, var,
# deinit, and init. There is no separate consume mode.
# Static parameters belong to the declaration and specialization key,
# not to the specialized function's runtime callable type or calling convention.
# Runtime callable parameter types retain these modes, for example
# func(imm T) T, func(deinit T) T, and func(init T) Box(T) | none. Taking a function
# value, aliasing it, or calling it indirectly does not erase its modes or
# deferred effects. Implementation support is tracked in ROADMAP.md.
# Callable compatibility requires identical parameter modes, parameter types,
# return types, and result access modes.
#
# A direct call may supply all parameters in declared order, including every
# static argument, or supply only runtime arguments in their declared order and
# infer every static argument. This is determined by argument count; partial
# positional lists of static arguments are not supported. An omitted static
# parameter between runtime parameters consumes no call argument. Inference
# uses runtime argument types, not runtime values or the call's result context.
# A parameter annotated with a static type parameter T infers T from its
# argument's type. A parameter annotated with a declared parameterized struct
# factory applied to static parameter names (for example Container(T, N)) infers
# those parameters from the same factory's nominal type specialization. Other
# type-valued functions are not inverted. A variant annotation with one dependent
# arm, such as T | none or List(T) | none, infers from the argument members left
# after removing the fixed arms. Thus int | none infers T = int for T | none;
# a bare none supplies no evidence for T. Multiple dependent arms are not
# partitioned by inference. Multiple uses of an inferred static parameter must
# agree on its canonical value; absent or conflicting evidence
# is an error. Inference cannot depend on an expected parameter type that itself
# requires the missing static arguments. Type-valued call annotations are
# checked after inference and do not provide an expected type while inferring.
# Explicit type values and exact-typed primitive compile-time values are
# supported. Each canonical tuple of static arguments identifies one function
# instance; aliases of the same type therefore reuse an instance. Runtime
# parameter and return types may refer to static type parameters. Static
# arguments are available as constants in the instantiated body but are not
# evaluated or passed at runtime. An unspecialized function with static
# parameters is not a value; partial application, indirect generic calls,
# arbitrary compile-time expressions, and compile-time-returning functions
# remain open.
func identity(static T: type, static N: int, value: T) T
    _ = N
    return value

# Runtime const and var bindings both own their values; const controls mutation,
# not ownership. A place is a local binding followed by zero or more fields.
# Ordinary place expressions borrow. Binding initializers, replacement
# assignments, struct fields, var arguments, and returns require owned values:
# a bare place is copied and must support copy, an explicitly transferred local
# or field (`name^`, `name.field^`) is moved and must support move, and a
# fresh result constructs directly in its destination. Aggregate `imm` arguments
# borrow through completion of the call; directly passed scalar arguments snapshot
# during preparation, before later arguments can mutate or consume their source.
# Explicit transfer is invalid in a borrowing
# context. Transfer into a distinct value destination requires move capability;
# passing consuming access to deinit does not require relocation capability.
# Transferring a field leaves that field uninitialized while independent fields
# remain accessible. Assigning a new owned value to that field reinitializes it.
# A whole-place use requires every field to be initialized; only initialized
# fields are destroyed. The fields initialized on every incoming path are
# available after a control-flow join. Ownership-carrying field transfers
# require movable fields and fieldwise or trivial-drop parents with
# no custom move; a deinit parameter may consume a field of its root, and a mut
# parameter must restore every transferred field before returning. A partially
# initialized parent cannot be used or borrowed as a whole. When an owned
# field is missing on only some join paths, it ends on paths retaining it if
# it supports automatic destruction; an explicit-drop field cannot be ended
# implicitly. A residual parent destroys only still-owned fields, and moving
# its last owned field leaves no parent drop obligation. Every reachable loop
# backedge must restore fields available on loop entry; a field absent on entry
# is ended on backedges where it was restored, subject to the same drop rule.
#
# Transfer makes the root unavailable on that path. Reading, transferring, or
# updating a field of an unavailable or possibly unavailable root is an error.
# Whole replacement assignment to a mutable root restores availability. At a
# control-flow join the root is available only if it is available on every
# incoming path. A root available on loop entry must be restored on every
# reachable backedge.
#
# Each successful initialization of an owning place starts a new ownership
# generation. A move ends the source generation without an automatic whole-source
# drop and creates the destination generation. A custom move hook still completes
# its source's lifetime under the deinit rules. Passing to deinit delegates the
# original generation's completion without relocation. Reinitializing the place
# starts another generation; lifetimes belong to generations, not lexical names.
#
# Automatic destruction follows Mojo's last-use (ASAP) timing. A generation is
# destroyed at the earliest completed subexpression boundary after its final
# use, rather than at the end of the enclosing statement or scope. A generation
# with no uses is destroyed immediately after its initialization completes.
# Evaluation order is unchanged: destruction is inserted only at boundaries
# that do not move an operation ahead of an earlier source operation.
#
# Replacement of a directly movable value retains its target through eager
# preparation of the owned right-hand side, then ends the old generation before
# installing the new value. This retention is an exception to earlier last-use
# destruction. Failure or a caller-directed exit during preparation preserves
# the target's initialization until ordinary exit cleanup. Explicit writes and
# transfers within the RHS retain their normal effects and are not rolled back.
# A borrow produced by the RHS keeps every owner it may refer to alive; replacing
# a source does not permit retaining a borrow into its ended generation.
#
# Lifetime analysis is path-sensitive. If a value is needed only on some branch
# successors, it is destroyed on the other outgoing edges before those branches
# begin. A conditional transfer consumes the generation only on the taken path;
# remaining owned paths destroy it automatically, but the root is still not
# usable after a join where it may have been transferred. A possible use in a
# later loop iteration keeps the generation alive across every backedge from
# which that use is reachable. Each loop exit ends it independently at the
# earliest boundary on that path.
#
# Return, break, and continue are control-flow exits and
# destroy every still-owned automatic generation that does not escape along that
# edge. No destruction is sequenced after a no-return expression because that
# continuation does not exist; values whose last uses precede it still end at
# their earlier boundaries.
#
# Uses through borrowed references and views, and uses performed by cleanup,
# keep every possible owner alive. When a borrowed result may refer to different
# owners on different paths, all possible owners remain alive until the result's
# final use.
#
# When several generations end at the same boundary, dependents are destroyed
# before owners that their cleanup may access. Otherwise, destruction is in
# reverse lifetime-start order. Consequently, operands and temporaries that
# start during one expression are destroyed in reverse evaluation order when
# their final-use boundary is shared. Aggregate field destruction remains in
# reverse field declaration order.
#
# Assigning a value to `_` is a non-consuming use that explicitly extends its
# lifetime to that point. The expression is evaluated once, but an owning value
# is neither copied nor transferred merely to perform the discard.
# A discard produces unit when used as an inline body or a conditional body's
# final value.
# Its behavior does not depend on whether another statement follows it.
# An inline function body with declared unit result evaluates its expression
# and discards the value. Explicit return expressions still check their result
# against the declared type.
_ = resource

# Lexical name visibility does not determine destruction timing.

#
# Transferred roots carry their drop obligation onward. Explicit-drop values
# are not automatically destroyed at last use: every ownership path must
# transfer the obligation or reach a deinit parameter before leaving the scope.
# This applies to explicit-drop fields, variant members, and borrowed
# temporaries as well. Replacement ends any still-live old value; only a
# deinit-authorized root may replace an explicit-drop value without first
# transferring it. That authority does not waive remaining field obligations.


# Destination construction
# An owning initialization supplies uninitialized storage for one result.
# A borrowed place copies into that destination; an explicitly transferred
# place moves into it. Copy and move capabilities are independent: an immovable
# source can be copied into distinct storage if it supports copy.
# Fresh struct initializers construct their fields at their final addresses.
# Calls receive the caller's result destination; conditional results, loop break
# results, and variant widenings propagate destinations to the selected result
# and its storage projections. These guarantees apply to direct
# and indirect calls, including ordinary calls, regardless of optimization.
# Delivering a fresh result does not itself invoke a copy or move hook.
# An immovable object retains its address throughout its lifetime, including
# destruction. Address stability does not extend or retarget existing borrows.
#
# A value that cannot move directly is identified with its storage. Field reads
# view that storage, and a conditional or loop result selecting an existing
# place borrows it without relocation in an ordinary expression; a deinit
# argument instead propagates consuming access to the selected result.
# A mutable local keeps one storage for its lifetime; field updates, mut
# arguments, and replacements write in place.
# Widening such a completed value would relocate it. Copying or transferring it
# into a larger variant constructs its active member in that destination, and
# extraction from a borrowed variant to a smaller variant copies the member.
# Consuming extraction transfers ownership; a single payload retains its current
# storage, while narrowing to another variant moves into that variant's storage.
# A fresh member result
# constructs in the larger destination's member storage, but a fresh result of
# a narrower variant is already complete and cannot widen. The destination type
# must be known before construction: from an annotation, an expected type, or
# conditional branches whose types are known without evaluation. Loop breaks of
# different types therefore need an annotation, as do arguments that infer
# static parameters, which are evaluated before their parameter types are known.
# An imm argument of a narrower type borrows a temporary of the parameter type
# valid through the call. A fresh argument constructs there; an existing value
# is viewed there only if it can move directly.
#
# An ordinary named local is an existing object, not a pending initializer.
# Returning it bare copies; returning it with '^' requests movement. Last use
# does not implicitly transfer it, and optional named-return elision cannot

# Deferred initializer parameters
# An init parameter represents pending construction of T, not an existing T
# or a cached value. Its argument is type-checked and participates in static
# inference without evaluating the expression. Binding it defers the entire
# expression, including producer arguments, copy hooks, and explicit transfers.
# Ordinary parameters retain eager argument evaluation in source order.
#
# Each init parameter is affine: construct or forward it at most once on any
# path. Any return may skip construction. A pending initializer cannot be copied,
# stored, returned as a handle, or escape the receiving call. Forwarding defers
# evaluation further. Captured values keep their ordinary lifetime obligations;
# skipped evaluation leaves their sources untouched.
#
# An init parameter cannot be read, borrowed as T, or inspected for fields
# before construction. Constructing it into a local consumes the initializer
# and establishes that local as the value's destination. An immovable local
# cannot subsequently be relocated into another destination.
func materialize(static T: type, init item: T) T
    return item # constructs directly in this call's result destination

func forward_initializer(static T: type, init item: T) T
    return materialize(T, item) # forwards once, without early construction
#
# Deferred expressions retain the lexical bindings and access needed for later
# evaluation. Their possible reads, writes, transfers, and reference origins are checked across argument preparation, the call, and forwarding.
# Required owners and storage must remain valid until those accesses end;
# conflicting consumption or mutation is rejected. Merely deferring a transfer
# does not perform it, nor does nonescaping capture require a public closure.
# Pending capture restrictions end when the receiving construction call ends,
# for every ordinary result, including collection converters and handled
# initializer expressions. Borrowed results retain their ordinary reference origins.
# Callable boundaries must preserve these effects rather than infer safety
# from a particular callee body, inlining, or a direct-call spelling.
# A caller may use a source afterward only if it remains available on every
# path reaching that use. Skipped evaluation does not consume its source;
# returning none or an error after a transfer does not undo it. A shared
# continuation may therefore see the source as possibly consumed.
#
# init describes deferred construction and ownership. Its result type describes
# all returned values, including absence or error alternatives. Deferral adds no
# return channel or implicit propagation. A region may return its own declared
# result or diverge; return to the caller and break/continue to an outside loop
# are rejected. A mismatch handler inside a deferred expression respects this
# region boundary. Partial construction on an ordinary nonlocal exit destroys
# completed subobjects in reverse initialization order, with dependents before
# owners. An incomplete object's whole-object drop hook never runs. Explicit
# drop obligations still apply. Completed aggregates use ordinary drop order.
# Runtime and compile-time execution obey the same rules.
#
# A deferred initializer is a control-flow boundary: it produces its value,
# or diverges. Return targeting the caller and break or continue targeting
# a loop outside the initializer are errors, not retargeted exits. Loops inside
# the initializer retain their own break and continue; called functions return
# normally. Forwarding, aliases, and indirect calls preserve this boundary.
# Ordinary eager argument expressions retain caller-directed exits.
# Deferred writes and completed transfers are not rolled back by an absent or error result.
# Reference escape, mutations of caller storage, and explicit-drop obligations still apply.


# References, places, and ownership
# A place is initialized storage with an access permission and a lifetime.
# `ref` denotes the same nonowning aliasing relationship in bindings, parameters,
# results, and fields; it is not a general type constructor.
# `const item = expression` and `var item = expression` own their values. When
# expression supplies a borrowed place, these bindings copy T and require T.copy.
# `ref item = expression` instead aliases that place, preserving its permission
# and storage identity. Reading item accesses T; assigning item replaces T at the
# original address. A ref binding cannot be retargeted and owns no destruction.
# Its initializer must supply an existing place; there is no implicit lifetime
# extension for an owned temporary. Type annotations describe the logical T and
# do not copy, coerce, or relocate the place.
#
# `ref` parameters preserve the identity and permission of caller storage.
# `mut` parameters require writable caller storage. `imm` and omitted modes keep
# their readonly access contract; `var` owns its prepared value. Requiring writes
# is expressed by mut, rather than assuming that a ref parameter is writable.
# Caller permissions are preserved when a ref parameter projects or forwards a
# place. There are no argument-site modifiers and no explicit origin annotations.
#
# Results distinguish ownership from identity: `func(...) T` returns an owned
# value, `func(...) ref T` returns a borrowed place, and `func(...) Ref(T)` returns
# an owned reference handle whose referent is borrowed. Callable types retain
# this result contract. A borrowed result can initialize an owned destination by
# copying T, initialize a ref binding by aliasing, or supply a borrowing argument.
# Borrowed results must designate caller or permanent storage; local and copied
# parameter frame storage cannot escape. Physical layout does not change this rule.
# In type annotations, ref binds one primary type: ref T | End is an owned variant
# with a reference-to-T alternative, while ref (T | End) borrows an existing whole
# variant. Parameter modes before the name remain separate from member storage.
# Alternative identity includes logical type and storage kind, so T | ref T has
# two alternatives. Owned nested variants flatten; references to whole variants
# do not distribute over their alternatives. No independently owned raw-reference
# value, address expression, or explicit dereference operator is introduced.
# A known reference alternative captures an existing place of its logical type
# without copying. If owned and reference alternatives can both accept that place,
# construction is ambiguous rather than choosing from copy availability.
#
# Field `ref` selects borrowed instead of owned storage. Parameter access and
# construction/destruction modes are separate concepts, not field modifiers.
# A field declared `pub ref value: T` stores a nonowning address while exposing
# logical type T. Initialization captures a place; assignment writes its referent.
# Copying the field copies its address and retained permission, without copying T.
# Destruction never destroys T through a reference field. Reference fields do not
# participate in inline containment cycles or inherit T's move/copy/drop duties.
# Ref(T) is the ordinary generic struct with one public reference field, value.
# It makes that relationship an ordinary value for replacement and containers.
# Replacing a handle does not retarget aliases already captured from its value.
# `Ref.from(place)` constructs a handle. There is no Ref(mut T), permission type
# argument, borrow binding modifier, address operator, or empty [] dereference.
# Box(T), in contrast, owns its initialized T and destroys it before deallocation.
#
# Permission is inferred from the capture origin. Readonly access restricts owned
# fields, but following a reference field preserves its captured referent authority
# independently of carrier constness. Copying a const handle preserves that authority;
# copying a handle captured from a readonly place never upgrades its permission.
# Replacing the carrier requires mutable carrier storage. Mutable references may
# coexist: there is no global exclusive-borrow rule. Calls retain the ordinary
# overlapping mut-argument checks. Owned storage cursors retain their existing
# readonly-backing rules; this reference-field rule does not upgrade those views.
#
# Box.borrow(ref self) returns ref T. Array, List, and Span get(ref self, index)
# return (ref T) | none after checking bounds. Their [] operators return ref T
# and panic on invalid bounds. `ref item = values[i]`
# aliases an element; `var item = values[i]` copies it. Containers of Ref(T) return
# ref Ref(T), which borrows the handle slot rather than silently unwrapping it.
# An owned getter remains an owned getter and cannot satisfy a ref binding.
# Explicit handles are requested with Ref.from(values[i]) or
# Ref.from(owner.borrow()). No separate get_mut or borrow_mut accessor is needed.
#
# `if value is Member` selects an existing variant payload; `ref item = value`
# inside that branch aliases it without copying or consuming it. A checked getter
# result is first saved, then tested with `is T`, then borrowed with `ref`.
# Matching uses logical type and can select owned or reference alternatives.
# An owned payload borrow retains its carrier and active-tag dependency; selecting
# a reference alternative follows its captured referent without also borrowing
# the carrier. Owned bindings copy a selected referenced value under normal copy
# rules and never consume the referent. Projection to a differently laid-out
# subset variant cannot create an alias.
#
# Lookup preserves existing element references. Destruction, relocation,
# reallocation, owner transfer, and changes to an active variant tag invalidate
# the affected storage references. Replacing an initialized value in stable
# storage preserves its slot while invalidating content-dependent views of the
# old value. Readonly references restrict access; they do not freeze their owner.
# Validated text views additionally depend on the byte contents remaining valid.
# Origins and captured permissions survive copies, fields, branches, loops, calls,
# function values, returns, and incremental recomputation.
#
#   var owner = [1, 2, 3]
#   ref item = owner[0]
#   item += 1
#   var handle = Ref.from(item)
#   handle.value += 1
#   const fixed_handle = handle
#   fixed_handle.value += 1
#   # Replacing fixed_handle is forbidden; writing its captured referent is not.
#
# Host storage and low-level operations:
# `std.memory.Box(T)` uniquely owns one initialized T in separately managed
# host storage. Its allocation returns Box(T) | none; moving preserves the storage
# address, and destruction destroys T before releasing that storage. Box has
# no copy capability; allocating a separate owner returns an explicit optional.
# Value construction and local binding do not themselves select allocation.
# Box(T).new has the signature func(init item: T) Box(T) | none. Box.new may infer
# T from the unevaluated initializer's type. The constructor obtains storage
# before evaluating any part of item, for every T and every initializer shape.
# Box.new(make(argument())) orders allocation before argument() and make().
# Box.new(if condition -> first else second) allocates before the condition.
# An initializer returning T | none constructs that entire variant. For an
# immovable T, Box(T | none).new(produce()) constructs its result in place;
# extracting T into a separate Box(T) would require moving the selected payload.
# Return alternatives do not bypass construction or deallocate a completed Box.
# Nested Box construction follows the same rule, with the outer allocation first.
#
# Struct initializers and function results construct directly in that storage.
# A bare existing value copies into it, including a copyable immovable value;
# an explicit transfer moves into it and requires move capability. Custom hooks
# use the same destination rules. No caller-written producer wrapper or distinct
# constructor is required for different capabilities. A transferred immovable
# value remains invalid. T must be automatically droppable.
#
# Allocation refusal returns none and skips the entire initializer. Otherwise
# construction produces T in its final slot and the constructor returns the Box.
# Panic and divergence have their ordinary behavior. An optional/error value
# returned by the initializer must be part of T; it never signals constructor failure.
# Box has no separate duplication API. Consuming take(T, owner) or
# take(T, owner^) uses deinit access to the Box; extraction of T still
# requires direct movement in the host API.
# Box.borrow and Box.take are ordinary wrappers for borrow(T, owner) and
# take(T, owner), respectively. Descriptors returned by view construction and
# slicing are owned values, not references to newly constructed descriptors.
# Nonnegative zero-byte host allocations (zero elements or zero-sized T)
# succeed with a distinct, stable storage address; the provider may reserve
# a minimal region to supply it.
# Zero-sized values still run their destruction hooks. Negative counts and
# layout overflow return none.
#
# `std.memory.Allocation(T)` uniquely owns uninitialized storage. Its layout
# comes from the layout domain selected by the execution target and location,
# the element count, and alignment; the checked byte size is count times that
# domain's element stride, which is aligned even for zero-count requests.
# Alignment is at least the natural alignment for T in that domain. Overflow
# returns none before allocation. The logical count remains separate from the byte layout.
# It must be consumed by deallocation, which releases storage but does not
# destroy elements. unsafe_initialize(T, mut allocation, index, init value)
# constructs into a caller-proven uninitialized element slot and returns unit.
# Allocation and index evaluate eagerly; value stays deferred until construction.
# The method form uses the same ordinary signature and destination rules.
# Planned unsafe_initialize_all(T, N, mut allocation, init value: collection_literal(T, N))
# constructs slots 0 through N - 1 with caller-proven capacity and initialization.
# unsafe_take(T, mut allocation, index) still requires directly movable T in
# the host API.
# unsafe_destroy(T, mut allocation, index) destroys an initialized element at
# its address without moving it. unsafe_borrow(T, ref allocation,
# index) returns ref T. A ref binding aliases the slot; an owned binding copies
# T if copying is supported. These operations require caller-proven bounds and initialization
# state; destruction and borrowing also require the caller to prevent
# conflicting aliases or invalidation during use. They are not safe initialized
# access. Box, Ref, and List are in std.prelude; raw allocation requires an explicit
# std.memory import. Ref(T) owns its handle, retaining the borrowed referent's
# origins. Borrowed results and reference fields expose T directly, as described
# above. Existing caller storage is passed by address for ref and mut parameters.
# Mutations remain visible on failure; a failed call supplies no borrowed result.
# Calls reject overlapping mutable and borrowed arguments and reject transferring
# an owner that also supplies another argument or indirect callee's borrow.
# Allocation methods use the same allocate, deallocate, unsafe_initialize,
# unsafe_borrow, unsafe_take, and unsafe_destroy names as their free functions.
# Their ordinary wrappers preserve initializer timing and ownership modes.
# An uninitialized Allocation(T) has no live T origins; unsafe operations with
# reference-containing elements cannot return references to callee-local owners.
# Known slots track captures separately: replacement, extraction, and destruction
# remove old captures, and extraction transfers them to the result. Unknown
# indices retain all possible dependencies. The caller proves bounds and initialization.
# Allocation(T).capacity() returns its allocated element count, including for
# zero-sized T. List capacity is derived from that count rather than stored twice.
# std.memory.List(T) owns Allocation(T) and a contiguous initialized prefix
# of length elements within capacity allocated slots. Creation returns List(T) | none;
# negative capacity fails. Zero capacity still owns a distinct allocation.
# List(T).filled(imm value: T, count: int) returns List(T) | none and requires copyable T.
# It allocates exactly count slots once, then constructs each element by one
# ordinary copy of value, which is not consumed. Negative count fails.
# Destroying a List destroys only the initialized prefix, in reverse order,
# then deallocates the storage. Its allocation and counters are not exposed for
# external mutation. Only directly movable, automatically droppable elements
# may be appended, removed, or relocated by the dynamic List API. Reference fields
# and reference-containing elements retain their captures through these operations.
# Literal construction also supports immovable elements.
# List growth allocates replacement storage before disturbing initialized
# elements; allocation failure leaves the original contents intact. reserve
# relocates in reverse index order. unsafe_take extracts the owned value with
# its contained referent origins, independently of the old slot. Internal slot
# construction inherits only its initializer's failure; supported moves are
# ordinary, so relocation needs no optional result after allocation succeeds.
# The initialized count remains unchanged, and the old allocation is released
# after all elements have been relocated. `get(index)`
# checks 0 <= index < length and returns (ref T) | none, with a present reference
# inheriting permission from the receiver. An empty
# List has no initialized element, even for an immovable T; append still
# rejects elements that cannot move directly. slice(bounds)
# resolves a Range against the initialized prefix and returns
# Span(T) | none. span() borrows the complete initialized prefix with backing permission
# inherited from the receiver. Lookup preserves existing element aliases. Writes preserve
# the identity of an initialized slot and invalidate content-dependent views;
# reallocation or destruction invalidates loans into ended element storage.
# Dynamic indices can conservatively share an owner dependency. Moving a List handle does not
# inherently relocate heap elements, but owner transfer invalidates prior borrows.
# remove(index) fails unless 0 <= index < length, without changing the List.
# Success returns the owned element and shifts the suffix, preserving order and
# capacity. Removed and relocated slots end their lifetimes; earlier slots remain
# stable. After bounds checks, removal neither allocates nor fails. Captured
# references follow their referents independently of the old slot. Append prepares
# its owned argument eagerly; failed growth preserves contents and cleans that argument.
# Potential reallocation or unknown-slot mutation conservatively invalidates loans,
# even when runtime inputs avoid mutation.
#
# Span(T) is a copyable nonowning contiguous initialized range, not an
# allocation or a container owner. Array also supplies span(). Span
# owns no destruction; Ref designates one initialized element and owns none either.
# Span.len() is initialized length, never reserved capacity. get checks bounds
# and returns ref T | none; slice(bounds) checks nonnegative, overflow-safe bounds
# and preserves permission. Array and List expose the same range-based slice
# operation. There is no separate public start/size slicing API. Empty endpoint
# slices are valid, including for
# zero-sized elements. Unsafe allocation-span constructors require caller-proven
# initialization of the complete range. No safe view exposes spare storage.
# from_array and unsafe_from_allocation use ref inputs and capture their backing
# permission. Permission belongs to the captured origins, not a type argument.
# A const Span supplies readonly access; copying it into a mutable binding cannot
# upgrade that captured access. Copies, fields, calls, branches, and loops retain
# attenuation. Indexed replacement requires a mutable receiver and writable
# backing; setters remain explicit and are not synthesized from ref getters.
# as_imm explicitly attenuates backing permission. Static storage is readonly.
# Readonly access does not freeze the backing owner. All views retain backing-owner
# and storage-change dependencies; readonly ranges additionally depend on contents.
# Span(byte) and BytesView are arbitrary bytes, not validated UTF-8 text.
# StringView maintains that additional guarantee through validation and invalidation.
#
# Returned borrows retain every source they can actually reference. The compiler
# infers private return-origin and write contracts from function bodies, including
# recursive calls. Callers substitute their places and contained references;
# unrelated arguments do not become artificial lifetime dependencies. Callable
# types retain result ownership. A known function value keeps its inferred
# contract. An unknown callable retains every possible source, requires writable
# inputs wherever its signature permits writes, and supplies readonly results.
# No source-level origin annotations are required.
#
# A function may return a borrowed input's place or references stored inside a
# prepared value. Ref(T) owns its handle, so returning that handle does not borrow
# the callee's handle slot. Ref and mut parameters preserve caller identity.
# Inline storage belonging to a copied imm parameter, an owned parameter, or a
# local cannot escape the call. Heap storage behind a copied descriptor retains
# its caller's owner; the descriptor frame does not own those allocated bytes.
# All possible origins must remain valid through subsequent use. Owner transfer,
# destruction, reallocation, and active variant changes invalidate affected loans.
# A slot reference can survive replacement of its value; references into the old
# value's owned allocations cannot. Captured access and current access paths are
# independent of ownership. A var binding cannot upgrade a readonly capture.
#
# Views provide non-owning access to existing data, including collection slices.
# They may be returned from functions and stored in other values when their
# lifetime and access dependencies remain valid. Copying a view does not copy or
# acquire ownership of its backing data. Every possible backing owner must
# remain alive through each dependent use, including uses through returned or
# stored views.
# Lifetime tracking must also reject uses invalidated by changes to the backing
# storage, such as collection reallocation. Keeping the owner alive alone is
# insufficient. Lifetime and access dependencies are inferred; when they cannot
# be proved safe, the compiler rejects the view. Other view type syntax remains open;
# adopting these guarantees does not require Mojo's exact spelling. Device
# storage and raw foreign addresses are deferred.


# Storage domains and future allocation
# These contracts extend the host model; provider selection, non-host locations,
# and address spaces have no public API yet. Keep these dimensions independent:
# - Value type: the meaning and operations of T.
# - Target representation: layout rules for the target's storage domain.
# - Allocation provider: policy and mechanism for obtaining and releasing storage.
# - Memory location: the concrete memory domain and accessible execution contexts.
# - Allocation layout: resolved byte size and alignment at that location.
# - Address space: the target-level access class, such as global or workgroup.
# - Lifetime dependency: every owner and resource required to remain live for access.
# Stack and heap are allocation or lifetime strategies, not memory locations or
# address spaces. A particular device is a location, not an address space: two
# devices may both offer global space while their allocations are inaccessible
# to each other. T does not change with its storage location or strategy;
# storage and reference abstractions carry the facts needed to access it.
# Construction uses its context's destination, not an allocation strategy chosen
# by a struct initializer. Separately managed dynamic storage is explicit:
# allocation does not construct values, and construction does not allocate
# unless the called owning abstraction does so. Registers, inline or automatic
# storage, or no storage may be used whenever the difference is unobservable.
#
# A typed allocation selects a provider, a concrete location, and a resolved
# byte layout independently. The execution target and location select the
# compatible layout domain, not the provider or value type. The representation
# includes element stride and field or variant offsets. Compatibility must be
# established for T and its contained types; coincidental host size is not proof.
# Access from a second target requires a verified compatible representation or
# explicit elementwise conversion, not an assumed bytewise copy.
#
# A resolved AllocationLayout contains byte size and alignment, not logical
# element count. A typed request binds it to T, its target representation,
# location, and nonnegative count. Alignment is a nonzero power of two and at
# least T's natural alignment in that domain; element stride is a multiple of
# that alignment, including for zero-count requests. Count times stride is
# checked before calling the provider. The provider may reject a stricter
# alignment, location, or layout it cannot support, or reserve extra storage
# internally; success satisfies the requested size and alignment. It cannot
# change the element stride or reinterpret another target's representation.
#
# Allocation returns an optional owner of uninitialized storage.
# The handle retains location, count, original layout, and deallocation authority.
# That authority is self-contained or depends on provider and location resources
# that must remain alive; dependent references retain those resources too.
# Allocation failure leaves provider and location ownership with the caller.
# A resolved request cannot outlive resources needed to validate its location.
# A convenience API may bind provider and location without erasing their separate
# meanings. A device context may supply both location authority and the resource
# used by a provider, without making device identity an allocation strategy.
# For every supported location, successful zero-byte allocation has a distinct,
# stable identity suitable for zero-sized element access and destruction, or
# allocation fails. This grants no raw-address arithmetic or foreign-memory access.
#
# Address space belongs on a typed Ref access path, not on T or its provider,
# independently of writable permission. Each target defines its supported spaces
# and their accessible locations. Concrete device identity remains runtime state
# retained by an allocation or device resource, not a distinct T for each device.
# Access requires a compatible execution context and address space; host code
# cannot dereference device-only storage. Cross-location transfer is explicit,
# not a cast of the value or reference type. Initial transfers are synchronous;
# asynchronous transfer needs an explicit completion resource keeping both
# allocations alive until completion.
# Device allocation is initially host-side; it does not imply allocation from a
# kernel. Workgroup and private storage have different lifetime and scheduling
# rules and use explicit kernel storage constructs, not dynamic allocation.
# Other locations have no public allocation or access APIs until their target
# layouts and access rules are implemented. Raw-address and foreign-memory
# operations remain deferred.

# Static structs
# 'static struct' is a struct expression modifier: it produces a nominal struct
# type whose instances may exist only during compile-time execution. The named
# declaration 'static struct Name' is sugar for 'static Name = static struct'.
# The binding's static modifier governs evaluation and immutability of the
# binding; the struct's static modifier governs runtime eligibility of instances.
# A parameterized static struct declares a type-valued factory returning a
# static struct, with every factory parameter implicitly static.
# Declared and generated static structs follow ordinary struct identity,
# specialization, initialization, visibility, namespace, and ownership rules.
# The modifier is preserved through aliases and factory specializations; it
# does not introduce structural identity or change the source-site identity rule.
#
# Static struct instances are compile-time data, not deferred expressions.
# They may be stored in static bindings, supplied as static arguments, and
# constructed, read, mutated, copied, moved, and dropped during compile-time
# execution as their ordinary access and ownership capabilities permit. Local
# const and var bindings inside compile-time execution may hold such instances;
# the struct modifier does not itself make instances or fields immutable.
# They have no runtime storage layout, rather than a zero-sized runtime layout,
# and cannot be materialized in runtime bindings, arguments, results, or storage.
# An ordinary parameter or result of a compile-time-only type restricts that
# function to compile-time execution. A static parameter of that type does not
# prevent runtime execution of the specialized function.
#
# Structs, tuples, and variants whose stored contents include a compile-time-only
# type are themselves compile-time-only, even without an explicit modifier.
# Namespace declarations do not contribute stored contents. Ordinary structs
# remain usable during compile-time execution without the modifier. Static
# structs do not force their uses to execute at compile time; a use requiring
# runtime materialization is a source error. Namespace functions are not
# implicitly compile-time-only and may produce runtime-capable values using
# static arguments without carrying static struct instances into runtime storage.

static S.read_a = func(imm value: S) int -> value.a

func S.read_a(imm value: S) int -> value.a

# the same module. The struct and declaration may be in different files. Each
# qualifier must name a declared struct namespace, or a primitive namespace in
# its registered prelude; imported types cannot be extended. A function written
# lexically inside a struct has the same namespace
# meaning as this qualified form. Lexical declarations remain necessary for a
# generated namespace because its identity includes the factory specialization.
# value.function(args) desugars to S.function(value, args), where value has
# type S. Both forms obey the same argument access and ownership rules, and
# prepare the receiver and remaining arguments left to right. An init argument
# defers evaluation until construction; a deinit receiver consumes in place.
# Callable values stored in the namespace also support this receiver insertion;
# callable instance fields are called directly without inserting the receiver.
# Fields and ordinary namespace declarations share one name scope; duplicate

# namespace declaration, unqualified names search its enclosing struct
# namespaces before module declarations and the defining file's imports.

# static values, and nested structs are private to their defining module by

# Field visibility
# Fields are private to the struct's defining module by default: every file of
# that module can name them; other modules cannot. `pub` makes a field part of
# the struct's public representation. A generated struct's defining module is
# its factory's; specialization and re-export do not change field visibility.
# Visibility is checked at every field projection: reads, writes, borrows,
# consuming moves, and field names in a struct initializer. A visible field is
# readable, and writable wherever access to the enclosing value permits
# mutation. Naming an inaccessible field is a privacy error, not a missing
# field.
# T{...} is structural initialization, not a special constructor. Because it
# names every field, any inaccessible field prevents structural initialization
# of the complete value; ordinary functions such as Interval.new provide
# validated construction. A struct without fields can be initialized wherever its type is
# accessible.
# Field privacy restricts field access, not the value: other modules may move,
# copy, pass, return, and drop it according to its ownership capabilities, and
# fieldwise or custom hooks act on every field. Public fields therefore carry no
# invariant that their module relies on. A `pub` field's declared type must not
# name a declaration hidden from importing modules.
pub struct Point
    pub x: int
    pub y: int # other modules may write Point{x = 1, y = 2}

pub struct Interval
    start: int
    end: int

    pub func new(start: int, end: int) Interval | none
        if start > end -> return none
        return Interval{start = start, end = end}

# Ownership properties and defaults:
# move = trivial | fieldwise | none | func
#        defaults to fieldwise if every direct field can move, otherwise none.
# copy = trivial | fieldwise | none | func
#        defaults to none.
# drop = trivial | fieldwise | explicit | func
#        defaults to trivial if every field's drop is trivial, otherwise fieldwise.
# 'trivial' invokes no field hooks; 'fieldwise' recurses through fields.
# An explicit trivial strategy requires every direct field to have the same
# trivial capability. An explicit fieldwise move or copy requires every direct
# field to support that operation. Function-valued hooks receive stable
# owner-qualified compiler identities and their required signatures are
# validated before use.
# 'func' means a complete function expression used as a custom, infallible hook.
# Its sole parameter name is immaterial. The required signatures are:
# copy = func(imm self: S) S
# move = func(deinit self: S) S
# drop = func(deinit self: S) unit
# A custom hook replaces that operation for the complete struct. Fieldwise
# strategies invoke nested custom hooks in declaration order for copy and move,
# reverse declaration order for drop, and operate only on a variant's active
# member. A move hook receives consuming access to the original source, with
# no preliminary move or copy. A copy hook borrows the original source. Both
# construct their result in the operation's final destination.
# A custom move hook constructs a fresh result, for example from transferred
# fields. A move or drop hook completes its source's lifetime under the ordinary
# deinit rules: no repeated whole-source drop, but remaining fields still need
# cleanup. Nested values invoke their selected hooks normally, even when those
# hooks have the same specialization as the enclosing hook.
# There is no active-hook redispatch suppression. Moving the whole source again
# inside its move hook, including 'return self^', recursively requests that move
# operation; it does not request a builtin fallback. Likewise, 'return self'
# inside a copy hook requests another copy. Use trivial or fieldwise strategies
# for compiler-provided default behavior, or construct a fresh result explicitly.
# Hook entry and result delivery introduce no extra copy or move. Operations
# explicitly requested inside the hook follow the same rules as other code.
# The logical effects of selected hooks are observable and cannot be omitted
# merely because storage could be reused.
# Potentially failing duplication is an ordinary function returning an optional,
# not an implicit copy operation.
# Without copy support, an existing value passed to a var parameter requires
# transfer with '^'. A deinit parameter consumes the original value in place.
# move = none requires construction in final storage and a stable address.
# Directly containing an immovable value makes the containing struct immovable;
# indirection does not.
# drop = explicit requires every ownership path to transfer the value and its
# obligation elsewhere or pass it to 'deinit' before its lifetime ends.

# Primitive values and function references have trivial move, copy, and drop.
# A variant moves or copies fieldwise when every member supports that operation,
# and otherwise does not support it. A variant drops trivially when every member
# does; otherwise it drops fieldwise according to its active member.

# Capability-backed ownership members
# T.copy exists exactly when T supports copy, with logical type func(imm T) T.
# T.move exists exactly when T supports move, with logical type func(deinit T) T.
# These compiler-provided namespace members select the same ownership operation
# as implicit copying or explicit transfer into a distinct destination. They
# are not wrappers that implement copying by returning self or moving by
# returning self^. Custom hooks supply the selected operation's body.
# Type-qualified calls, instance calls, aliases, and indirect calls preserve
# these signatures and invoke the operation once. value.move() and T.move(value)
# consume the receiver/source; neither first copies or moves it into a parameter.
# Their results construct directly in the caller's destination.
# The member names copy and move are reserved for these operations. Ownership
# properties remain in their separate declaration scope. Arbitrary namespace
# functions cannot manufacture a capability or replace its member.
# Capability validation precedes member availability. A where-condition may
# test these members and their callable types; a missing capability fails the
# condition, while an invalid ownership definition remains a diagnostic.

# Converters
# imm and static value converters and consuming collection init converters are
# implemented. ROADMAP.md records implementation limits separately from these rules.
# A converter declares an implicit conversion from a source type to a target
# type. It has no declaration name. Its signature has exactly one
# value parameter, which receives the converted expression; every other
# parameter is static and inferred from the source and target types together.
# A static parameter that neither type determines is an error. The value
# parameter's mode follows its type: static for a compile-time-only type,
# including static structs and int_literal, init for collection_literal, and
# imm otherwise, so inserting a converter never consumes an existing value.
# Converters are ordinary functions with their declared result type. Their
# source and target types determine selection before evaluation; builtin source
# widening is allowed, but no converter chains are inferred. A none alternative
# is data and never establishes a control boundary. A consuming init converter
# uses the same deferred construction, region boundaries, and cleanup rules as
# any init consumer. Its supplied expression must construct the declared type.
# Pattern matching selects types directly and never calls a converter.


# A converter is a top-level declaration in a module that owns its source or
# target type. A struct is owned by its defining module, a parameterized struct
# by the module declaring its factory, and compiler-owned primitive and literal
# types by the standard library. Aliases resolve to canonical types first.
# Structural variants, tuples, and callable types have no owner, so the other
# type must supply one. A pub converter applies in every module; a private
# converter applies only in its declaring module. Imports never add or remove
# candidates.
#
# For a statically known source type T, `T.U` first looks up an ordinary type
# member. If no member exists, U resolves as a type name in the surrounding
# scope, including static type parameters and aliases. Exactly one declared
# converter from T to U yields a callable value with that converter's actual
# parameter and result types and modes. Generic converters specialize from
# those types. Lookup checks the selected declaration's constraints without
# executing its body. Missing or ambiguous conversions and failed constraints
# make an `is` membership test fail; ordinary uses diagnose them.
# No identity, widening, or per-member variant adapter is synthesized. An
# applicable converter with a wider input retains that input in its callable
# type. A converter whose source parameter is static needs a concrete value
# and cannot be obtained from its source type alone. Bind a parameterized or
# qualified target type to an alias or static type parameter before lookup.
# Existing conversion expressions, including variant composition, keep their
# normal behavior. To accept identity as well as a declared converter, use:
func accepts_text(static T: type) int
where T is String or T.String is func(imm T) String -> 1
#
# Conversion applies only where the expected type is already known: bindings,
# assignments, arguments, returns, struct initializer fields, and the results
# propagated to them, such as conditional branches. A value whose type equals
# the expected type is not converted. Built-in variant widening also takes
# precedence over converters, preserving an already compatible value.
# Otherwise the candidates are the built-in literal defaults, a
# converter from the source to the expected type, and, for an expected variant,
# a converter from the source to one member followed by widening. Exactly one
# candidate must apply; none is a type error and several are an ambiguity error
# at that use. Overlapping declarations are diagnosed only where they are
# ambiguous. An integer literal whose default type is a member of the expected
# variant takes that type without considering other candidates. `where`
# clauses are checked on the selected converter; failure is a source error.
# If no whole-value conversion applies to a source variant, conversion applies
# separately to every member. Each member must widen to the expected type or
# have one applicable converter to that type or one of its members. A missing,
# ambiguous, or constrained-out member conversion rejects the use.
# The source is evaluated once; only the active
# member's conversion executes. Reference alternatives use their referents for
# conversion unless the expected type already accepts the stored reference.
# Identity members retain ordinary borrowing and copying rules; converting a
# variant never implicitly copies a noncopyable member merely to inspect it.

# and unique List members of expected variants retain their element context.
# Empty static expansion needs an expected element type if no retained item or

# Spreading borrows collection elements and copies through ordinary conversion
# and ownership rules; it does not consume individual source slots. Comprehension
# bindings use ordinary for modes. Output references retain their source lifetimes
# and cannot survive invalidating polls. Elements construct in final storage;
# an ordinary exit destroys the completed prefix in reverse order and releases
# owned sources, cursors, and List storage. Completed side effects are not undone.
# Growable contiguous results require movable elements. A statically bounded
# result can reserve its complete static bound before constructing immovable

# Implicit List allocation failure, including growth, panics. List(T).collect

# Match
# Patterns compose recursively: every tuple position accepts any pattern below,
# including nested tuples, ranges, type tests, captures, and wildcards.
# Literal: match an equal value. '_': match anything without binding.
# A bare name resolving to a type tests the active alternative against that type.
# Type names include aliases, qualified names, and specialized types; unions
# select their structural intersection with the subject. Type patterns bind
# nothing and refine reads of the original matched place on the arm edge.
# A fresh bare identifier matches anything and binds it immutably in the arm.
# Tuple: match the stated arity and apply each element pattern recursively.
# (x, y) captures two elements; (0, y) tests one and captures the other;
# (x, _) ignores the second without copying it. (x) groups a pattern and
# (x,) matches a singleton tuple. () still matches unit, not an empty tuple.
# Tuple patterns do not positionally destructure nominal structs.
# A name that does not resolve to a type introduces a new arm-local capture;
# it never tests equality against an outer value. Duplicate names and shadowing
# are source errors. Sibling arms can independently reuse the same names.
# Tuple captures have their elements' logical types; corresponding captures
# across compatible tuple alternatives must agree. No variant-of-tuples to
# tuple-of-variants distribution is inferred. Reference storage and authority
# remain independent of those logical element types.
# Match headers have no leading 'is' or 'pattern as name' capture syntax.
# Payload extraction uses ordinary bindings in the arm body, e.g.
# 'const name = subject' or 'ref name = subject', after a type pattern.
# Captures own immutable values like const bindings: an existing place supplies
# a copy, while a fresh or explicitly transferred owner supplies ownership.
# `ref name` aliases the matched place under ordinary permission and lifetime
# rules. Further copies or aliases are explicit ordinary bindings in the arm body.
# Capturing a whole variant preserves its stored alternatives; owning logical
# type extraction copies a selected reference referent, never consumes it.
# The subject evaluates once without an arm-result expected type. Tests inspect
# without consuming on mismatch. The first matching arm runs. Returning none
# or an error from its body returns ordinary data and never tries another arm.
# Literal patterns use built-in value equality, not user equality or arbitrary
# converters. Supported domains are int, byte, bool, unit, none, compile-time
# integer literals, and registered String/StaticString/StringView text. A literal
# selects one compatible logical type; int wins over byte as in construction.
# Other multiple compatible types are ambiguous. Text compares decoded UTF-8
# bytes including NUL, without copying the subject. Byte literals require 0..255.
# Range: a..b excludes b; a..=b includes b. Omitted bounds extend to the ends
# of the selected numeric domain; inclusive syntax requires an upper bound.
# Bounds are compile-time integer expressions (int, byte, or int_literal),
# including static names and calls. Runtime captures and relative bounds are
# errors. Matching uses built-in integer comparisons and invokes no converters
# or membership hooks. A range selects one compatible numeric logical type,
# preferring int over byte and int_literal as integer literals do. Its interval
# intersects that type's domain: 0..256 covers every byte. Empty or reversed
# ranges are errors; a range disjoint from every compatible alternative is an
# incompatible pattern. Explicit none endpoints denote omitted bounds, as in
# ordinary range construction. Range syntax here is a pattern, not a Range value.
# Coverage uses the typed domain and prior patterns, independently of constant
# folding. Bool, byte, unit, and none have finite domains. Integer and text
# literal lists require a catch-all or type pattern for the remaining values.
# Integer ranges and literals combine by interval coverage; adjacent ranges may
# jointly cover the complete domain, including at any depth in a tuple pattern.
# Every match must be exhaustive; a fully covered arm is an error.
# Arm values join like conditional branches. Recursive type patterns refine
# corresponding original fields; captures remain ordinary immutable bindings.
# Ordinary transfer, explicit-drop, reference escape, and ASAP cleanup rules
# apply on every selected arm and nonlocal exit; cleanup is not delayed to the
# lexical end of an arm. Failed tests retain the subject for subsequent arms.
# An arm can follow its pattern with and and an ordinary condition expression.
# All captures become visible only after the complete pattern matches, then
# remain visible in its condition and selected body. Conditions short-circuit
# as bool expressions. A false guard cleans attempt-local captures and tries
# the next arm. A selected body never retries. Completed side effects persist.
# A guarded arm does not establish exhaustive coverage, even if its condition
# is constant true. Tuple coverage combines unguarded element patterns across
# arms, preserving correlations between positions and nested alternatives.
# For (bool, int), (true, _) and (false, _) together are exhaustive; for

# Ranges and for iteration
# a..b excludes b; a..=b includes b. Endpoints are evaluated exactly once,
# left to right. Arithmetic binds more tightly than a range; a range binds more
# tightly than comparisons. The result is an ordinary
# reusable std.range.Range value, not an active cursor or a collection of
# items. Both endpoint fields have type int | std.range.FromEnd | none, so their
# presence and absolute or relative form can vary at runtime without changing
# the range type. Original endpoints and inclusivity are retained rather than
# normalized. String conversion uses .. or ..= and retains ^ on relative bounds.
# ..b, a.., and .. use none for omitted bounds; explicit none endpoints are
# equivalent. A trailing .. at the end of a line omits the upper bound.
# Inclusive syntax requires an upper endpoint. Iteration requires two int
# endpoints; omitted or relative bounds cannot supply an iteration length.
# Iteration and reversal panic for missing or relative endpoints; step_by fails.
# These finite integer ranges initially iterate upward. A start greater than
# the end produces an empty iteration; x..x is empty and x..=x contains exactly x.
# This does not make reversed bounds valid for slicing.
# Range.contains supports membership only when both stored endpoints are absolute
# integers. x in a..b checks a <= x and x < b; x in a..=b checks a <= x and x <= b.
# Empty or reversed ranges fail membership. Omitted and FromEnd bounds fail
# membership, including when those bounds are selected at runtime. Inclusive
# comparisons do not increment the upper bound and support the full int domain.
#
# Prefix ^n constructs an ordinary std.range.FromEnd value, equivalent to
# std.range.from_end(n), independently of caller imports or shadowing. It evaluates
# its operand once and binds like other unary operators: use ^(n + 1) to include
# arithmetic in the distance. Postfix value^ remains ownership transfer.
# Construction stores the distance; applying it checks 0 <= n <= length before
# subtracting, then resolves to length - n. Invalid distances fail without
# wrapping or clamping. Standard integer indexing still rejects negative indices.
# values[^1] selects the last element, values[^n..] the last n elements, and
# values[..^n] excludes the last n elements. values[1..=^1] includes the last
# element. ^0 denotes the past-end boundary: valid as an exclusive slice bound,
# invalid as an element index or inclusive upper bound. Relative positions and
# stored ranges resolve anew against each receiver's current initialized length,
# never its capacity. Range.resolve(length) explicitly resolves a stored range
# to absolute, exclusive (start, limit) bounds.
# The old inclusive spelling ..^ is not an alias for ..=: it now means an
# exclusive range with a relative upper bound.
#
# Array, List, Span, BytesView, and StringView accept slice(bounds). Omitted
# starts resolve to zero and omitted exclusive ends to initialized length.
# Exclusive slicing requires 0 <= start <= limit <= length. Inclusive slicing
# requires 0 <= start <= limit < length and includes limit; it checks bounds
# before incrementing the limit. An inclusive none upper endpoint fails.
# Equal exclusive endpoints are empty, including at length. Negative, reversed,
# and out-of-bounds inputs fail rather than clamp. Slices own only a view handle,
# preserve backing permissions and lifetimes, and expose no spare capacity.
# Text slice positions are byte offsets; StringView also checks UTF-8 boundaries.
# Array, List, Span, and BytesView accept integer or FromEnd element indices
# through get and brackets; Array, List, and Span also accept them for element
# assignment. Explicit standard-library overload sets select element indexing or
# range slicing. StringView supports range slicing, not element indexing. Relative
# text distances count bytes, not characters; UTF-8 boundary checks still apply.
# No standard range setter or bulk slice assignment is defined.
#
# reversed() reverses the actual sequence, including a stepped sequence.
# step_by(positive_factor) selects the first item and then every factor-th item
# of the receiver's sequence. It fails for a zero or negative factor, even on
# an empty range. Both return std.range.RangeSequence values, distinct from raw
# Range bounds; a RangeSequence is not a contiguous slice argument. Repeated
# stepping composes sequence selection. Neither the
# signed endpoint distance nor a composed stride must fit in a positive int.
# Iteration checks the final item before advancing past it, so inclusive ranges
# ending at 2147483647 terminate without wrapping. Reversal and stepping do not
# add items outside the original sequence. Reversing an empty range is empty.

# Iteration protocol
# Iterators are ordinary structs specialized through static parameters, with no
# required traits, dynamic dispatch, yield, coroutine, or push protocol.
# Reference aggregate members provide the owned-carrier result model:
#   func next(mut self: Iterator) T | End
#   func next(mut self: Iterator) ref T | End
#   func next(mut self: Iterator) (ref A, ref B) | End
# A ref (T | End) result instead borrows an existing complete variant. Preserve
# the distinction between a reference member and an owned Ref(T) value; for must
# not implicitly unwrap Ref handles. Standard range and span cursors expose next
# and std.iteration.End, also exported by the prelude. next is the sole cursor
# protocol; there is no build flag, advance/current compatibility, or automatic
# fallback. General computed-member composition and automatic callable
# result-type discovery remains a separate, deferred interface decision.
# Ref has one type parameter; writable authority follows ordinary provenance,
# not a boolean type argument or a factory name that upgrades readonly access.
#
# End denotes normal exhaustion. Any error protocol must use explicit data.
# Loop lowering requires an owned std.iteration.End alternative in
# the poll result, independent of caller imports or shadowing. A reference-to-End
# alternative is not the exhaustion representation.
# With this union encoding, T must not be End or have End as a direct variant
# member. Containing an End field inside a struct is not ambiguous and is legal.
# Preserve the binding modes, source evaluation, and loop result rules below;
# default collection iteration remains a readonly borrow without element copies.
# An explicit consuming traversal is a separate collection capability.
#
# zip polls left to right and stops when either input ends. It may acquire one
# unmatched left item before the right input ends. It retains that item while
# polling the right and must discharge its ownership on exhaustion or failure.
# A queue or coroutine is not required; ordinary item storage and loan tracking
# still are. Mutable inputs follow ordinary overlap and invalidation rules.
#
# Borrowed aggregate results and fresh immovable destination construction through
# the result union are implemented. Type factories can select exact static
# result types and owned/reference delivery from explicit static arguments.
# Broader generic adapter interfaces require approval before implementation;
# they are not prerequisites for this protocol. Buffering does not permit later
# relocation. ROADMAP.md owns remaining library priorities and validation gates.
#
# for uses ordinary methods, not a special declaration kind or generator:
#   iter(...) Cursor          optional source-to-cursor factory
#   next(...) T | End         owned-item cursor operation
#   next(...) ref T | End     borrowed-item cursor operation
# Methods retain their ordinary receiver modes, ownership, and result types.
# Generic methods and callable fields follow ordinary member-call rules.
# No trait, associated item type, iter declaration, or yield syntax is required.
#
# The source is evaluated once. A named source is borrowed without copying;
# a fresh source is owned in the loop's setup scope. If an iter member exists,
# it is invoked once to prepare the cursor. An invalid explicit iter member is
# an error, not permission to fall back. Without iter, the source itself is the
# cursor: named cursor state resumes in place instead of being copied or reset.
# A factory's fresh result is owned, and a borrowed result remains borrowed.
# Ordinary cleanup and last-use rules apply to both source and cursor.
# An explicitly transferred source selects consume_iter when that member exists.
# Its signature determines effects and delivery; an invalid factory is an error.
# Without it, the loop owns the source and uses iter or next normally. Fresh
# sources use iter; transferring a view does not acquire its backing elements.
# List.consume_iter transfers the allocation and yields elements in forward order
# without copies or shifting. Elements must be directly movable and automatically
# droppable, with no owned End alternative that could be confused with exhaustion.
# Captured references retain their referents and permissions; aliases into an
# owned item depend on its poll carrier, independently of the former List slot.
# Break and return destroy remaining elements in reverse order
# and release storage. Even empty traversal consumes the List. Cursor and item
# follow independent last-use cleanup. Panic and process exit do not unwind.
#
# Each iteration calls next once and retains its result carrier. End means
# successful exhaustion; otherwise the item is extracted and the body runs.
# Source preparation, iter, next, and the body use ordinary function result
# types. A returned error alternative is an item unless the cursor explicitly
# interprets it. No return alternative silently becomes exhaustion.
# Even an underscore binding acquires the item once and performs its cleanup.
#
# The bare binding preserves the result's ownership but grants read-only use:
# an owned poll payload is owned, and a borrowed result is a read-only alias.
# const and var explicitly own the item, copying a borrowed result through its
# ordinary copy operation. var additionally permits mutation of that owned item.
# ref aliases an available place: a captured referent or an owned poll payload.
# It preserves available permission without upgrading read-only backing. An
# alias into the poll carrier cannot escape that carrier's lifetime; an alias
# following a reference member depends on its referent instead. An optional : Type
# annotation follows ordinary type checking and conversion rules.
# The binding is local to the body, cannot shadow a visible local, and is renewed
# for each iteration. It does not leak after the loop.

# Body values are discarded. Reaching its end or continue starts the next
# poll. Break exits without polling again; break values join with unit
# from exhaustion, using ordinary loop result rules. Return exits the enclosing
# function. Item, cursor, and source cleanup follow ordinary ownership on all
# exits, including failure. There is no separate for-else clause.
#
# Arrays, Lists, and Spans provide iter through an ordinary SpanIterator(T).
# It snapshots the initialized extent and borrows backing storage; next
# returns ref T | End with the captured backing permission. Iteration does not freeze
# owners. Relocation, destruction, transfer, replacement, and content-dependent
# views follow the same invalidation rules as explicit references and calls.
# A reference into stable backing may outlive the cursor, but not its owner.
# A view into a cursor's reused buffer cannot survive an invalidating poll.
#
# Adapters are ordinary cursor structs. An adapter that inspects an owned item
# must retain that exact item until returning it; polling upstream again is a
# different operation that may repeat effects or produce a different item. Borrowed items
# retain ordinary loan constraints. Buffering/forwarding does not permit moving
# an immovable value or retaining a deferred init expression as a stored value.
# Consuming traversal of collection storage is a separate library capability,
# not an implicit effect of a bare or const for binding.
