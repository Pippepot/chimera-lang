# Architecture

Durable compiler contracts live here. [syntax&semantics.txt](syntax&semantics.txt) owns language rules; [ROADMAP.md](ROADMAP.md) distinguishes implemented behavior from the target. The current execution path is in [PROGRAM_FLOW.md](PROGRAM_FLOW.md).

## Stage boundaries

- Compiler stages depend in data-flow order. Shared types in `src/structures.zig` do not import stages. Parser, semantic analysis, and codegen do not import query orchestration; the query engine remains compiler-independent.
- Query definitions supply dependencies and small protocols such as `TypeInterner`. Semantic analysis owns source traversal and issues; the interner owns canonical variant and callable identity and nominal struct identity.
- Nominal `StructIdentity` distinguishes declared items from generated source sites without creating separate runtime type kinds. Generated identities use an owner-relative node offset plus the enclosing static specialization. `GeneratedStructDefinition` resolves their fields through the same type interner; layout, ownership, initialization, interpretation, and codegen consume the common `StructDefinition` shape.
- Module and item queries own declarations, scopes, and shared semantic data. `ResolveStatic` resolves explicit `: type` aliases and nominal struct identities directly; every inferred or runtime-annotated initializer, including literals and symbolic aliases, crosses `AnalyzeComptimeThunk` and `ExecuteComptimeThunk`. Explicit `comptime` expressions, static arguments, and direct calls in type positions use the same boundary. Interpreted direct and indirect calls cross `ExecuteComptimeCall`, keyed by the concrete instance and canonical interpreted-argument tuple. `StructDefinition` owns ordered field names, types, source spans, ownership strategy overrides, and validated custom-hook identities independently of layout. Declaration shapes retain parameter modes before dependent types can be resolved; signatures and bodies operate per callable instance. Runtime calls and function references demand callee signatures, not bodies; type-valued functions are interpreted only and publish no runtime artifact.
- Source and lexical validation build a query-local expression graph before callable resolution. Typing constructs the sole control-flow graph; codegen consumes it directly. Add a separate lowering representation only when a transformation requires it.
- `AnalyzeFunctionBody`, `AnalyzeComptimeFunctionBody`, and `AnalyzeComptimeThunk` are typed publication boundaries. All validate names, annotations, operations, calls, joins, and returns before publishing the same type-specific IR; a thunk infers its result type and has no runtime parameters. The compile-time publications retain instruction source spans for reached execution diagnostics, while the ordinary runtime-body query omits them so source positions do not perturb its equality. Codegen trusts semantic facts and checks its own capabilities and resource limits.
- Expected source errors produce `structures.Diagnostic` values. Type-bearing diagnostics retain canonical `TypeId` values so presentation can render complete callable and variant structure through the interner. Missing or stale query state remains distinct from rejection; infrastructure failures use errors. Compile-time interruption and machine resource exhaustion are infrastructure failures, not source errors. Broken compiler invariants use assertions or `unreachable`, never user diagnostics. `src/diagnostics.zig` alone translates kinds into messages; presentation resolves types, paths, and source lines.
- Compile-time execution returns `CompileTimeOutcome`: a canonical runtime or type value, fallible failure, or compiler-control effect. The interpreter keeps canonical `TypeId` values separate from runtime payloads, and typed `const_type` plus type equality operations exist only in compile-time publications. One query helper owns translation of interpreter failures into source diagnostics, while the active typed instruction supplies the source span. Interpreted calls additionally return their canonical final argument tuple so typed mutable copy-back operations observe cached calls exactly as runtime calls do. `CompilerControl` accumulators propagate `exit(i32)` to the embedding driver without turning it into a diagnostic or terminating a query worker.

## Identity and ownership

- Query keys are small, pointer-free identities. Cached results own allocations or retain stable identities; they never borrow from replaceable inputs. Instantiated signatures and callable types share one representation containing ordered runtime mode/type parameter records, return type, and fallibility. A separate declaration shape retains all modes, including static positions, before substitution. Parameter names belong to body scope, not callable type identity, and signatures retain no AST nodes.
- Modules have interned entry-relative path identities. `ModuleCatalog` records existence (including dependencies on absent modules); `ModuleMembers` records current files and `FileModule` their ownership. `SourceRegistry` registers and refreshes all three consistently, retaining file IDs for unchanged paths and clearing removed memberships. It also registers the embedded standard-library files under reserved `std.<filename>` module identities. Module changes use input updates, never interner presence as an existence test.
- Declaration identity has a module origin; synthetic entry identity has a file origin. Neither stores a historical declaration location. `IndexModuleItems` validates the shared namespace and publishes current item locations, including owner-qualified hooks. `ResolveItem` depends on this membership-backed index, so removal and relocation replace its source dependencies.
- `CollectFileImports` publishes owned semantic syntax independently of declaration discovery. File binding and demand-driven export resolution consume it without evaluating declarations. `ResolvePreludeImports` resolves the embedded prelude once against its dedicated input and does not depend on the user module catalog. `ResolveFileImports` adds those exports as lowest-priority implicit bindings for user files unless that file explicitly imports `std.prelude`; the explicit statement replaces the default, including with an empty selection. Compiler-owned `std` modules are exempt from implicit inclusion. Namespace bindings record whether members are visible or the name only navigates to explicitly imported children. All export candidates for a name are validated across the module; equal identities merge. Active-path recursion distinguishes semantic name cycles from valid module cycles and re-export diamonds. `BuildModuleScope` combines module declarations with the defining file's imported declarations. `NameReference` separates namespaces, declaration instances, and canonical constants; module names never enter runtime IR. `StructNamespace` validates member names independently of layout, and qualified expressions dispatch to module exports, type namespaces, or typed value fields. `ValidateModuleGraph` uses a queue to validate imports and public exports without evaluating top-level statements.
- `ItemId` identifies a declaration; `InstanceId` identifies a declaration instance as an item plus an optional interned canonical static-argument tuple. `SpecializationArity` separates inherited arguments from a member's own arguments; namespace references, callable references, and static evaluation retain both. Canonical compile-time values have session-stable `CompileTimeValueId` identities. Ordered tuples of those identities are shared by specializations, immutable struct fields, and `CompileTimeCallKey`, whose separate interpreted-argument tuple memoizes calls. Identical instance-and-argument recursion is an exact cycle. Variant values retain their active member type and canonical payload identity. Declaration identity includes its optional owning item, optional generated source site, hook distinction, function/static kind, and stable name, and survives body edits and relocation. Function-valued struct properties are discovered as children owned by the declared struct or generated type factory; they reuse ordinary signature and body queries but remain outside module scope. Struct-definition analysis validates their exact copy, move, or drop callable shape and retains the hook `InstanceId`, including the enclosing specialization for a generated definition. Struct definitions introduce nominal type identity; static aliases preserve the canonical `TypeId` rather than introducing another identity. Static arguments never occupy runtime parameter or SSA entry slots.
- `TypeId` is a pointer-free, session-local identity. Primitives have reserved IDs, including compiler-only `type`; variants, callables, and structs share one discriminated interned type-data store. `type` has no runtime layout. The `InternedTypeId` index does not encode the type's semantic kind. Callable identity contains ordered parameter modes and types, return type, and fallibility, but not parameter names. Callable compatibility requires identical parameter modes. A compile-time runtime value keeps its payload representation type separate from the type exposed by a static annotation.
- `OwnershipCapabilities(TypeId)` owns default move, copy, and drop facts. Primitive and callable values are trivial. Variants aggregate over their members. Structs move fieldwise when every field can move, never copy by default, and drop trivially only when every field does. A struct may override those defaults with compatible `trivial`, `fieldwise`, `none`, `explicit`, or custom strategies; trivial and fieldwise overrides are validated against direct field capabilities. Invalid struct definitions, layouts, and ownership compositions publish no capabilities.
- Inputs and dependencies are recorded through the query context. Observable equality includes payload contents and diagnostics. Optional results inherit payload equality; use query-specific `eqlOutput` only when its semantics differ.
- Recomputations commit or discard fresh allocations, dependencies, and diagnostics together. Equal results retain allocations and `changed_at`; infrastructure failure preserves the last completed memo and permits retry. Input changes require an idle database.

## Typed values and control flow

- Expressions produce values; return and discard are uses, not operation kinds. Known operand types select operations such as `addi`, without redundant generic opcodes and type metadata.
- Source-use spans remain separate from reused value identities until diagnostics are complete. An error at an alias use points to that use, not to the expression that originally defined its SSA value.
- Every lexical const or var binding retains a stable source-graph place identity and one fixed type. Owned `var` and `deinit` parameters and borrowed `mut` parameters receive mutable place identities initialized from entry-block arguments; an `imm` parameter remains a borrowed value. Typing tracks place ownership availability at control-flow edges; joins conservatively distinguish available, transferred, and possibly transferred places. Mutable bindings additionally have current SSA values, and joins carry changed outer mutable values as block arguments. Immutable values continue to use dominance and do not become loop-carried arguments. Mutation and ownership tracking do not introduce memory-backed locals.
- Preserve exactly-once, left-to-right evaluation, including struct initializer source order. Reordering must be unobservable.
- Fallibility is success/failure control flow, separate from `bool` and `never`. Use one predicate-branch structure with type-specific operations. Logical composition connects edges; extraction carries a value on the success edge. Do not materialize boolean SSA values for fallible outcomes.
- Every block has one terminator. During typing, blocks retain mutable instruction sequences and instructions have stable build-time identities, so completed blocks and control-flow edges can be transformed without renumbering existing operands. After typed CFG transformations finish, publication flattens block instructions and assigns the final value-ID namespace. Typed block parameters and published instruction results share that namespace; function parameters are entry-block arguments. Calls and branches use separate flat operand arrays. Edges may be forward or backward and carry any number of arguments; edge copies are parallel.
- Typing owns query-local ownership generations, lifetime effects, completed-expression boundaries, and edge forwarding metadata. After CFG construction converges, functions with drop obligations run `src/lifetime.zig`, which borrows that metadata and computes reachability, generation availability, current SSA representations, backward demand, and an ordered path-sensitive cleanup or explicit-abandonment plan without importing typing. The solver indexes incoming and outgoing edges once; publication layout does not determine analysis order. Ending candidates are appended, then sorted and deduplicated by location and generation before validation or materialization. Path-completeness assertions run in safety-enabled builds. A planned cleanup value is the current representation at its location, so it dominates the boundary, block entry, or interposed edge block where typing uses it.
- `AnalyzeFunctionBody` reports explicit abandonment before mutating the CFG and publishes no body on that diagnostic path. Otherwise typing materializes the plan with ordinary type-specific calls, field accesses, variant dispatch, and branches, then flattens and renumbers the completed graph in `finish()`. Generated custom-hook calls retain their hook `ItemId` dependencies through ordinary call analysis and reachability. No ownership generation, lifetime effect, cleanup condition, or generic destruction operation crosses the publication boundary.
- Struct initialization keeps field operands in source order in a body-owned flat table; each operand carries its declaration field index. Typing resolves names, rejects unknown, duplicate, and missing fields, and publishes field coercions explicitly. Field access carries the resolved declaration index and field type. Field assignment is permitted only through a mutable local root. Compound assignment reads the leaf before its right-hand side; rebuilding then starts from the root's latest SSA value so right-hand-side updates to sibling fields survive. Fields do not have independent mutable identities. Codegen uses only these typed facts and `StructLayout` offsets.
- Semantic analysis owns type canonicalization, joins, and widening legality. Variant canonicalization flattens and orders members, rejecting source duplicates after alias expansion. Callable compatibility is invariant in parameter modes, parameter types, and return type. An ordinary callable widens to the otherwise-identical fallible callable, never the reverse. Typing publishes coercions explicitly through `FunctionValueUse`, `variant_coerce`, or `callable_coerce`; each variant coercion references typing's chosen destination tag for every possible source tag. Consumers do not rediscover legality or member compatibility. Branch-local extraction and pattern bindings must not refine existing bindings.
- Divergence is represented with `never` in joins and return-path analysis. Bare place reads carry provenance until a borrowing or owning use classifies them. Owning bindings, replacement assignments, struct fields, returns, and owned call arguments require copy support for a bare place; `^` transfers a movable local root and invalidates it, while a temporary is already owned. Conditional and loop joins carry a boolean copy predicate when only some incoming values are borrowed, so effectful custom copies run on exactly those runtime paths. Whole assignment restores a mutable root. `imm` calls borrow and reject explicit transfer. Mutable calls require an exact-typed mutable place, reject any same-root immutable or mutable argument whose field path overlaps, and copy the updated leaf back before later call cleanup. Borrowed mutable roots cannot transfer ownership or satisfy drop obligations. Source availability still ends at lexical control-flow transitions, while owned generations are destroyed at the earliest completed boundary after their final path-specific use. Simultaneous endings use reverse generation-start order; aggregate cleanup retains reverse field declaration order. Custom copy, move, and drop strategies lower to ordinary direct calls; fieldwise strategies recurse through struct fields and the active variant member only when a nested custom hook exists. Compiler-generated argument, result, and lifetime plumbing bypasses redispatch when typing the active hook itself. Explicit-drop generations must be consumed or reach a `deinit` parameter on every path; abandonment rejects analysis before cleanup materialization. Origin dependencies through pointers and views, independent partial-place lifetimes, and stable storage for immovable values remain future work.

## Representation and linking

- `TypeLayout(TypeId)` exposes only byte size and alignment. `VariantLayout(TypeId)` owns the variant payload offset and common layout; `StructLayout(TypeId)` owns declaration-order field offsets and common layout. Struct layout validates that its by-value containment graph is acyclic, traversing inline variants but not callable signatures. Variants use an aligned `u32` tag followed by storage aligned for the largest payload, with tail padding. Callable values are one aligned `u64` code address. A future `sizeof` consumes the common layout boundary.
- Arguments, spills, and copies use the full layout. The current internal convention returns exactly four-byte values in `eax`, other nonzero-sized values in caller-provided stack storage, and zero-sized values without a machine result. Every successful return sets `edx` to one; fallible failure sets it to zero. This lets an ordinary function reference widen to a fallible callable without a wrapper. The payload location is unchanged and meaningful only on success. Callers reserve a fixed outgoing area. Mutable borrows use copy-in/copy-out: the callee writes each final parameter value back to its incoming argument slot on every return, and the caller reloads each slot before another call can reuse that area. This is not an external platform ABI.
- Per-function compilation emits owned code, relocations, alignment, and symbolic references. Direct calls use relative relocations; function values use absolute address relocations and indirect calls invoke the loaded address. Whole-program construction resolves both forms and emits ELF. Cached reachability includes referenced function values and provides one deterministic breadth-first order for linking and debug output.
- Current startup calls the file's synthetic, unit-returning top-level entry, then exits with zero. Top-level statement values are discarded; `main` has no special status.
- Inline, never-typed `exit` is temporary. At compile time it is an explicit compiler-control effect represented as a structured outcome and propagated without terminating the compiler process directly. Migrate runtime services to compiler-seeded declarations and ordinary symbolic calls when another service, target, or foreign call justifies runtime-symbol linking, preserving that context-dependent `exit` behavior. Remove dedicated `exit` machinery then; do not grow it into general intrinsic dispatch.
