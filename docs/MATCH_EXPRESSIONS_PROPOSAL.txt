# Match design decision: bare types, tuple patterns, and ordinary conditions
# syntax&semantics.txt owns the implemented language rules.
# ARCHITECTURE.md owns compiler boundaries; ROADMAP.md owns deferred work.
# This decision supersedes the earlier proposals in this file.

match point
    (0, 0) -> origin()
    (x, y) and x > y -> above(x, y)
    (x, y) -> remaining(x, y)

# Approved implementation
# A fresh name introduces an immutable capture, recursively through tuples.
# A name resolving to a type tests the active alternative without binding.
# Ordinary const declarations still require their normal explicit initializer.
# Patterns support literals, ignores, grouping, singleton commas, and nesting.
# ref x explicitly aliases a place; bare x owns its capture under existing match
# rules. (ref x, y) independently selects reference/owning modes per element.
# Captures become visible after the complete pattern, in its condition and body.
# No shadowing, duplicate captures, or comparisons against a same-named outer local.
#
# The first and separates the leading pattern from an ordinary condition
# expression. The condition retains normal and/or/not precedence and ordinary
# Boolean semantics; an or in it cannot bypass the leading pattern.
# No comma headers or extra guard if/where keyword are introduced.
# Functions receive explicitly written arguments. No predicate discovery,
# signature-based implicit application, bool adaptation, or smart casts.
# General value in collection predicates work in ordinary arm conditions.
# They use the collection's contains method and establish no exhaustive coverage.
#
# Evaluate the subject once; try arms in source order. A false condition retries
# after attempt cleanup. A selected body never retries another arm.
# Existing expected-result construction and branch joins remain authoritative.
# Guarded arms do not establish exhaustiveness. An unconstrained unguarded tuple
# pattern covers compatible tuple alternatives; partial product coverage is not
# solved by inferring relationships between arbitrary predicates.
#
# Borrowed elements make actual copies after structural success, before conditions.
# Conditions and body inspect the same copy, including observable copy hooks.
# Rejection ends independent copied owners through normal cleanup.
# Fresh/transferred owned fields stay in place during testing and acquire capture
# ownership on selection. Rejection preserves the retained original. Reference
# fields remain borrowed referents; naming one never acquires referent ownership.
# Conditions cannot consume or invalidate protected subject/capture storage through
# aliases. Unrelated effects persist. Copy/drop/callee effects are included, and
# conditions' references can reach the body only with stable places and origins.
# Explicit-drop, ignored-owner, reference-authority, and ASAP obligations remain.
#
# Tuple alternatives retain their actual layouts and storage modes. Captured
# element types must agree across compatible alternatives; no inferred
# variant-of-tuples to tuple-of-variants distribution or positional struct access.
# Bare type names test variant alternatives without binding or smart casts.
# Ordinary name resolution distinguishes types from fresh arm-local captures.
# Type aliases, qualified names, specialized types, and type unions are supported.
# Leading is and match-specific as-name captures are removed. Payload access
# uses typed name: Type captures or ordinary typed bindings in the selected body.

# Deferred separately
# - nominal struct tests and struct-field capture spelling;
# - relative comparison patterns and direct membership arm syntax;
# - expression initializers in headers;
# - sequence/rest patterns, extractor protocols, and pattern boolean algebra.
# No @, prefix as Type, match-specific as-name captures, const-prefixed match
# captures, or ordinary named-struct destructuring is introduced.
